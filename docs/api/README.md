# docs/api

- `ENDPOINT-MAP.md` — **committed.** Every DockHand operation with the tier dockhand-mcp assigns it. Generated by `scripts/gen-endpoint-map.py`.
- `src/dockhand_mcp/client/env_required.py` — **committed.** The operations whose environment query parameter (`env`, or `envId` on exec) the spec marks required; the client refuses a request to one of them without it (#5). Generated by `scripts/gen-endpoint-map.py --env-required`.
- `dockhand-openapi-1.0.49.json` — **not committed** (`.gitignore`: `docs/api/*.json`). DockHand's own OpenAPI document (`GET /api/docs`). Sessions S1, S2, S3a and S3b need it; the maintainer either leaves a copy at this path (git-ignored, and the session greps it) or attaches it to the session. S0, S4 and S5 don't need it. To regenerate both generated files after a newer spec:

```powershell
python scripts\gen-endpoint-map.py docs\api\dockhand-openapi-<version>.json > docs\api\ENDPOINT-MAP.md
python scripts\gen-endpoint-map.py --env-required docs\api\dockhand-openapi-<version>.json > src\dockhand_mcp\client\env_required.py
git diff docs\api\ENDPOINT-MAP.md   # any change = a tier decision to record in ARCHIVE §14
git diff src\dockhand_mcp\client\env_required.py   # record in ARCHIVE §14; update tests\test_env_required.py's list to match
```

`tests/test_endpoint_map.py` compares both files with the generator's output for the local spec. Where the spec is absent (CI) those tests skip, and `tests/test_env_required.py` still pins the env-required list.
